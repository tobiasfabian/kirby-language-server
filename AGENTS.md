# AGENTS.md

A language server for Kirby CMS projects (`src/`) and the extensions that start it: for Nova (`Kirby.novaextension/`) and for VS Code (`vscode/`).

## Commands

- `npm run build`: bundles `src/server.js` into `Kirby.novaextension/Server/server.cjs` and `vscode/dist/server.js`, and the VS Code client into `vscode/dist/extension.js`
- `npm run package:vscode`: builds `vscode/kirby-language-server-<version>.vsix`
- `npm test`: unit tests and an LSP test against the built server; build first
- `npm run lint`: ESLint
- `npm run read-kirby -- path/to/kirby`: regenerates `src/field-properties.json` (the options of each field type) and `src/field-methods.json` (Kirby's field methods) from a Kirby 6 checkout
- `nova extension validate Kirby.novaextension`: checks the bundle for publishing
- `nova extension activate Kirby.novaextension`: opens it in Nova for development

## Conventions

- Built for Kirby 6 only. Older Kirby versions don't matter: no version checks, no special cases. The source of truth is Kirby 6 itself: its documentation and release notes (https://getkirby.com/releases/6/blueprints) and its source code (e.g. `src/Blueprint/Normalizer.php`, the field classes in `src/Form/Field/`). The blueprints of real projects are no reference; they may be wrong.
- `src/field-properties.json` and `src/field-methods.json` are generated by `scripts/read-kirby.mjs`; don't edit them by hand.
- Warnings about undefined variables in templates are only shown when every controller of the template could be read completely and the template defines no variables in ways that can't be followed (`extract()`, `$$name`, `include`). Snippets aren't checked: their variables come from whoever calls them.
- Plain modern JavaScript with JSDoc, no TypeScript. Tabs, as `.editorconfig` and ESLint say.
- The server only reads files. It never starts Kirby or runs PHP, so it stays fast and safe in any project.
- No false warnings: a warning is only shown for literal names. Names built at runtime are skipped. Registered snippets and collections are read with the small parser in `src/php.js`, which knows the nesting: `'collections'` inside `'api' => [...]` are API collections, not Kirby collections.
- Translation keys are only reported as missing with a Warning when every source could be read; if a plugin builds its translations at runtime (JSON, YAML), it's an Information instead. Kirby's own keys come from `kirby/i18n/translations/*.json` (the file per site language; es → es_ES.json if there is no es.json) and are offered after the project's keys.
- Before changing what counts as a call, run the server against a few real projects and check that the warnings it shows are real.
- In PHP files only the PHP code counts (`phpRegions()` in `src/variables.js`); the HTML around it is neither completed nor checked.
- PHP's language server (Intelephense) comes first: completions don't repeat what it knows from types (`@var`, typed parameters, `$this`), `@method` docblocks and `*.stub.php` files (`phpKnowledge()` in `src/server.js`). Offer only what it can't know.

## VS Code

- The client (`vscode/src/extension.js`) starts the same server bundle with `vscode-languageclient` over IPC (`--node-ipc`) in VS Code's own Node.js; `test/vscode.test.js` talks to it that way.
- Keep features in the server, not in a client: both extensions should behave the same. Only what an editor can't do over LSP belongs in its client (like Nova's Open Referenced File command).
- `vscode/package.json` is the extension manifest, separate from the repo's `package.json` (which sets `"type": "module"`); the bundles in `vscode/dist/` are CommonJS `.js` files because that folder's `package.json` has no `type`.

## Nova gotchas

- `Process` events are methods: `process.onStdout(cb)`, not `process.onStdout = cb`.
- Nova doesn't expand `~` in config paths; use `nova.path.expanduser()`.
- The bundle is `server.cjs`, not `.js`: the repo's `package.json` sets `"type": "module"`, which would make Node load a CommonJS bundle as an ES module.
- Errors the user should see go through a notification (`showError()` in `main.js`), not only the console.
- While Nova's built-in PHP server (Intelephense) runs, Nova sends `textDocument/hover` and `textDocument/definition` in PHP files only to it, never to this one; completions from all servers are merged. With Intelephense off, hover requests arrive and are shown, but ⌘-click sends no definition request (tried with Location and LocationLink responses). Verified with Nova 14.1 by logging requests in the server. That’s why Open Referenced File is a command that calls `client.sendRequest('textDocument/definition', …)`.
- Nova announces `codeLens` support in `initialize`, but shows no code lenses from this server.
- A shortcut is only bound if it's free (`ctrl-cmd-o` was taken). The extension uses `cmd-opt-ctrl-o`.
